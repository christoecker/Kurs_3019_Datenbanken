    SQL-Abfragen mit BestTec (03.11.2026)

    Übung

    Worum geht es?

    Ihr habt Kapitel 7 des Lehrbriefs gelesen und kennt die Bausteine einer SELECT-Abfrage vom Papier. Heute probiert ihr sie zum ersten Mal an einer echten Datenbank aus. Wir gehen dabei immer gleich vor: Wir beginnen mit einer praktischen Frage an die Daten, überlegen gemeinsam, welche Angaben die Datenbank dafür braucht, und leiten daraus die Syntax ab. Anschließend führen wir die Abfrage aus und schauen uns an, worauf man achten muss. Wo SQL Server von der Schreibweise im Lehrbrief abweicht, steht es auf der Seite SQL Server und Lehrbrief: Abweichungen.

    Lernziele

    • Ihr könnt aus einer fachlichen Frage an die Daten eine SELECT-Abfrage ableiten und erklären, wofür SELECT, FROM, WHERE und ORDER BY jeweils zuständig sind.
    • Ihr könnt erklären, warum bei Abfragen über mehrere Tabellen eine Verknüpfungsbedingung nötig ist, und das Ergebnis einer Abfrage mit AND und OR vorhersagen.

    Kurzer Rückblick ca. 3 Min.

    1. Wozu dient ein Fremdschlüssel, und woran erkennt ihr in einem Relationenschema, welche Tabellen miteinander zusammenhängen?

      Musterlösung anzeigen

      Ein Fremdschlüssel verweist auf den Primärschlüssel einer anderen Relation und bildet so die Beziehung zwischen Datensätzen ab. Im Relationenschema erkennt man ihn an der Kennzeichnung „FK“; die Tabelle, auf die er verweist, ist die verbundene Tabelle. In BestTec verweisen z. B. ma.abtnr und prj.abtnr auf abt.abtnr.

    2. Ihr habt in Kapitel 7 die Grundform einer Abfrage gelesen. Aus welchen drei Teilen besteht sie, und was leistet jeder Teil?

      Musterlösung anzeigen

      SELECT bestimmt die Spalten der Ergebnistabelle, FROM legt fest, aus welchen Tabellen die Daten gelesen werden, und WHERE nennt die Bedingung, die eine Zeile erfüllen muss, um ins Ergebnis zu gehören. WHERE ist optional; fehlt es, gehören alle Zeilen zum Ergebnis.

    Das Szenario: BestTec ca. 4 Min.

    BestTec ist ein Unternehmen der Automatisierungstechnik, das Steuerungssysteme entwickelt und seinen Kunden auch Schulungen anbietet. Das Unternehmen ist in Abteilungen gegliedert, die an verschiedenen Standorten sitzen (Gütersloh, Verl, Paderborn, Bielefeld, Münster). Jeder Mitarbeiter gehört zu genau einer Abteilung, hat eine Tätigkeit, ein Grundgehalt und kann zusätzlich eine Provision bekommen. Die meisten Mitarbeiter haben einen direkten Vorgesetzten, der selbst Mitarbeiter ist. Abteilungen führen Projekte für Kunden durch; jedes Projekt wird von genau einer Abteilung verantwortet.

    (Fallbeispiel nach Lehrbrief, Anhang 9.2, S. 97–98.)

    Das Relationenschema besteht aus drei Relationen:

    Relation abt

    Schlüssel Attribut Wertebereich optional?
    PK abtnr int nein
    – bezeichnung string (eindeutig) nein
    – sitz string nein

    Relation ma

    Schlüssel Attribut Wertebereich optional?
    PK manr int nein
    – name string nein
    – job string nein
    FK vorgnr int (verweist auf ma) ja
    – gehalt decimal nein
    – prov decimal ja
    FK abtnr int (verweist auf abt) nein

    Relation prj

    Schlüssel Attribut Wertebereich optional?
    PK prjnr int nein
    FK abtnr int (verweist auf abt) nein
    – kdnr string nein
    – titel string nein

    Den Datenbestand, mit dem wir heute arbeiten, findet ihr auf der Seite BestTec: Datenbestand.

    Legt die Datenbank jetzt auf eurem Rechner an: Öffnet in SQL Server Management Studio zuerst das Skript uebung-05-besttec-datenbank.sql und führt es aus, danach das Skript uebung-05-besttec-testdaten.sql. Speichert die Dateien dafür vorher über „Link speichern unter…“.

    Spalten auswählen: Projektion ca. 5 Min.

    Eine einfache Liste

    Die Personalabteilung möchte eine Liste mit Name, Tätigkeit und Grundgehalt aller Mitarbeiter — ohne Vorgesetzten, Provision und Abteilung. Welche Angaben braucht die Datenbank, um das zu liefern?

    Lösung 
    SELECT name, job, gehalt
FROM ma;

    Die Datenbank muss wissen, welche Spalten das Ergebnis haben soll (SELECT) und aus welcher Tabelle sie stammen (FROM). Das Ergebnis hat 20 Zeilen, eine je Mitarbeiter. Wollt ihr alle Spalten, schreibt ihr SELECT * — das ist zum Ausprobieren praktisch, in echten Abfragen nennt man die gewünschten Spalten besser ausdrücklich. Jede Abfrage liefert wieder eine Tabelle (Relation) als Ergebnis.

    Rechnen und umbenennen

    Die Geschäftsführung fragt nach dem Jahresgehalt jedes Mitarbeiters (zwölf Monatsgehälter). In der Tabelle gibt es dafür keine Spalte. Muss man die Tabelle erweitern?

    Lösung 
    SELECT name, gehalt * 12 AS jahresgehalt
FROM ma;

    Nein: In der Auswahlliste dürfen Werteausdrücke stehen, also Berechnungen mit Spalten und Zahlen. Mit AS bekommt die berechnete Spalte einen Namen. Die Berechnung gilt nur für das Ergebnis — in der Tabelle ma ändert sich nichts.

    Doppelte Werte entfernen

    Welche Tätigkeiten kommen im Unternehmen überhaupt vor? Was passiert, wenn man einfach nur die Spalte job abfragt?

    Lösung 
    SELECT DISTINCT job
FROM ma;

    Ohne DISTINCT steht jede Tätigkeit so oft im Ergebnis, wie es Mitarbeiter mit dieser Tätigkeit gibt (20 Zeilen). DISTINCT entfernt doppelte Ergebniszeilen — übrig bleiben die 8 verschiedenen Tätigkeiten.

    Zeilen auswählen: Selektion ca. 7 Min.

    Vergleiche und Listen

    Wer in den Abteilungen 10 oder 20 verdient mehr als 4000 €? Ausgegeben werden sollen Name, Gehalt und Abteilungsnummer. Womit sagt ihr der Datenbank, welche Zeilen ins Ergebnis gehören?

    Lösung 
    SELECT name, gehalt, abtnr
FROM ma
WHERE abtnr IN (10, 20) -- (1)!
  AND gehalt > 4000; -- (2)!
    1. Eine Liste: abtnr IN (10, 20) ist die Kurzform für „Abteilung 10 oder Abteilung 20“.
    2. Ein Vergleich; weitere Operatoren sind =, <>, <, <= und >=. Der WHERE-Teil enthält die Bedingung, die jede Zeile erfüllen muss; hier sind beide Bedingungen mit AND verknüpft.

    Ergebnis: 6 Zeilen (Hansen, Langer, John, Karl, Meyer, Sorge).

    Muster in Texten

    Welche Mitarbeiter der Abteilungen 20, 30 oder 40 haben einen Namen mit genau vier Buchstaben, dessen zweiter Buchstabe ein „o“ ist? Wie beschreibt man ein solches Muster in SQL?

    Lösung 
    SELECT name, abtnr
FROM ma
WHERE abtnr IN (20, 30, 40) AND name LIKE '_o__'; -- (1)!
    1. LIKE vergleicht einen Text mit einem Muster. Der Unterstrich _ steht für genau ein beliebiges Zeichen, das Prozentzeichen % für beliebig viele (auch null) Zeichen. '_o__' passt also auf vierbuchstabige Namen mit „o“ an zweiter Stelle (Ergebnis: Born und Dorn). Textwerte stehen immer in einfachen Hochkommas.

    Noch eine Kurzform für Bereiche: gehalt BETWEEN 2800 AND 3000 schließt beide Grenzen ein.

    Bedingungen kombinieren ca. 6 Min.

    Gesucht sind die Mitarbeiter der Abteilungen 10 oder 20, die Manager sind oder mehr als 5000 € verdienen. Formuliert die Bedingung zuerst so, wie ihr den Satz sprecht, und sagt vorher: Wie viele Zeilen erwartet ihr? Vergleicht dann mit dem tatsächlichen Ergebnis.

    Lösung 
    -- Ohne Klammern: AND bindet stärker als OR
SELECT name, abtnr, gehalt, job
FROM ma
WHERE abtnr IN (10, 20) AND job = 'Manager' OR gehalt > 5000;

-- Mit Klammern: wie in der Fragestellung gemeint
SELECT name, abtnr, gehalt, job
FROM ma
WHERE abtnr IN (10, 20) AND (job = 'Manager' OR gehalt > 5000);

    Die erste Abfrage liefert 6 Zeilen — darunter Meier (Abteilung 40) und Kron (Abteilung 50), die gar nicht gemeint waren. Der Grund: AND bindet stärker als OR. Die Datenbank liest die Bedingung als „(Abteilung 10/20 und Manager) oder Gehalt über 5000“. Erst mit Klammern um die OR-Bedingung erhält man das gewünschte Ergebnis mit 4 Zeilen (Hansen, Karl, Meyer, Sorge). Merkregel: Sobald AND und OR gemeinsam vorkommen, setzt man Klammern.

    Sortieren ca. 3 Min.

    Die Geschäftsführung möchte eine Gehaltsliste: das höchste Gehalt zuerst, bei gleichem Gehalt alphabetisch nach Name. Woran erkennt die Datenbank, in welcher Reihenfolge sie die Zeilen liefern soll?

    Lösung 
    SELECT name, gehalt
FROM ma
ORDER BY gehalt DESC, name; -- (1)!
    1. Die Sortierung steht in ORDER BY am Ende der Abfrage. ASC (aufsteigend) ist der Standard, DESC kehrt die Richtung um. Mehrere Sortierkriterien werden durch Kommas getrennt; das zweite gilt nur bei Gleichstand beim ersten.

    Ohne ORDER BY garantiert die Datenbank keine bestimmte Reihenfolge — verlasst euch nie darauf, dass das Ergebnis „zufällig richtig“ sortiert ist.

    Mehrere Tabellen: der Verbund ca. 12 Min.

    Was passiert ohne Verknüpfung?

    Gesucht ist für jedes Projekt die Bezeichnung der verantwortlichen Abteilung. Die Tabelle prj kennt nur die Abteilungsnummer — die Bezeichnung steht in abt. Schreibt einmal beide Tabellen in den FROM-Teil, ohne weitere Bedingung. Wie viele Zeilen erwartet ihr?

    Lösung 
    -- Ohne Verknüpfungsbedingung: jede Abteilung mit jedem Projekt (5 * 4 = 20 Zeilen)
SELECT abt.bezeichnung, prj.titel
FROM abt, prj;

    Die Datenbank kombiniert jede der 5 Abteilungen mit jedem der 4 Projekte: 20 Zeilen, von denen die meisten inhaltlich unsinnig sind (z. B. „Zentrale“ mit dem Projekt „PeakControl“, das zu Engineering gehört). Dieses Ergebnis heißt Kreuzprodukt. Bei ma und abt wären es schon 100 Zeilen.

    Zeilen über den Fremdschlüssel verknüpfen

    Welche Bedingung sortiert die unsinnigen Kombinationen aus? Gesucht ist dabei eine Liste mit Abteilungsnummer, Bezeichnung, Projekttitel und Kundennummer, geordnet nach Abteilungsnummer.

    Lösung 
    -- Schreibweise des Lehrbriefs: Verknüpfungsbedingung im WHERE-Teil
SELECT x.abtnr, x.bezeichnung, y.titel, y.kdnr
FROM abt x, prj y -- (1)!
WHERE x.abtnr = y.abtnr -- (2)!
ORDER BY x.abtnr;

-- Gleiche Abfrage mit INNER JOIN (diese Schreibweise liefert auch KI meist)
SELECT x.abtnr, x.bezeichnung, y.titel, y.kdnr
FROM abt x
INNER JOIN prj y ON x.abtnr = y.abtnr -- (3)!
ORDER BY x.abtnr;
    1. Weil abtnr in beiden Tabellen vorkommt, muss ein Spaltenname eindeutig angegeben werden; dafür vergibt man im FROM-Teil kurze Aliase (x, y).
    2. Zusammengehörig sind genau die Zeilen, in denen der Fremdschlüssel prj.abtnr gleich dem Primärschlüssel abt.abtnr ist. Diese Gleichheit steht als Verknüpfungsbedingung im WHERE-Teil; übrig bleiben 4 Zeilen.
    3. Die zweite Abfrage ist gleichwertig, nur mit der Schreibweise INNER JOIN … ON. Sie begegnet euch in KI-generierten Abfragen häufig, deshalb solltet ihr beide Formen lesen können.

    Eine Tabelle mit sich selbst verknüpfen

    Wer sind die Untergebenen von Kron, und wie weit liegt ihr Gehalt unter seinem? Gesucht sind Name, Tätigkeit, Gehalt und die Gehaltsdifferenz. Vorgesetzter und Untergebener stehen beide in der Tabelle ma — wie löst man das?

    Lösung 
    -- Schreibweise des Lehrbriefs: Verknüpfungsbedingung im WHERE-Teil
SELECT x.name, x.job, x.gehalt, y.gehalt - x.gehalt AS delta
FROM ma x, ma y -- (1)!
WHERE y.name = 'Kron' AND x.vorgnr = y.manr; -- (2)!

-- Gleiche Abfrage mit INNER JOIN
SELECT x.name, x.job, x.gehalt, y.gehalt - x.gehalt AS delta
FROM ma x
INNER JOIN ma y ON x.vorgnr = y.manr -- (3)!
WHERE y.name = 'Kron';
    1. Die Tabelle ma wird zweimal in den FROM-Teil aufgenommen, mit zwei verschiedenen Aliasen: x ist der Untergebene, y der Vorgesetzte.
    2. Verknüpft werden sie über x.vorgnr = y.manr. Das nennt man einen Selbstverbund. Ergebnis: Klaas (Differenz 2000) und Beier (Differenz 2500).
    3. Gleichwertig mit INNER JOIN: Die Verknüpfungsbedingung steht dann hinter ON, im WHERE-Teil bleibt nur die Auswahl von Kron.

    Gesamtergebnis ca. 2 Min.

    Lösung

    Jede Abfrage, die ihr heute geschrieben habt, folgt diesem Gerüst:

    SELECT [DISTINCT] Spalten oder Ausdrücke
FROM Tabellen
WHERE Bedingungen
ORDER BY Sortierkriterien;
    Die Frage lautet … … also brauche ich
    Welche Spalten soll das Ergebnis haben? SELECT (mit AS und DISTINCT)
    Aus welchen Tabellen kommen die Daten? FROM (bei mehreren Tabellen mit Aliasen)
    Welche Zeilen gehören ins Ergebnis? WHERE (Vergleich, IN, LIKE, BETWEEN, AND/OR/NOT)
    Wie hängen die Tabellen zusammen? Verknüpfungsbedingung: Fremdschlüssel = Primärschlüssel
    In welcher Reihenfolge soll das Ergebnis stehen? ORDER BY

    Die Datenbank arbeitet dabei gedanklich von innen nach außen: Sie bildet zuerst die Tabellen aus FROM, wählt dann mit WHERE die passenden Zeilen aus, berechnet danach die Spalten aus SELECT und sortiert zuletzt. Gruppierung und Unteranfragen kommen als Nächstes dazu.

    Betreutes Selbststudium

    Worum geht es?

    Jetzt wendet ihr die Syntax selbstständig an: zuerst beim Filtern und Sortieren, dann beim Verbund. Anschließend dreht sich der Blick um — ihr bekommt fertige Abfragen, sagt ihr Ergebnis vorher und entscheidet, welche Abfrage zu einer Anforderung passt.

    Warum schreibt ihr die Abfragen überhaupt selbst? Ihr schreibt in diesem Kurs später nicht regelmäßig eigene SQL-Skripte. Das Schreiben ist hier ein Teil des Lernwegs: Wer jede Klausel einmal selbst benutzt hat, versteht, was ein fremdes Statement — zum Beispiel eines, das eine KI erstellt hat — wirklich aussagt, und kann beurteilen, ob es zur Anforderung passt. Darum geht es in dieser Einheit. KI-Werkzeuge nutzt ihr dafür bewusst noch nicht.

    Lernziele

    • Ihr könnt Abfragen mit Projektion, Selektion, Sortierung und Verbund selbstständig formulieren und ihr Ergebnis auf Plausibilität prüfen.
    • Ihr könnt das Ergebnis einer fremden Abfrage von Hand herleiten.
    • Ihr könnt aus mehreren ähnlichen Abfragen die passende auswählen und typische Fehlerbilder benennen.

    Aufgabe 05: BestTec-Abfragen anwenden und bewerten

    Bezug zu Lehrinhalten

    Die Übung oben und Lehrbrief Kapitel 7 (7.1–7.5). Die Datenbank BestTec habt ihr in der Übung angelegt.
    SQL-Server-Besonderheiten: SQL Server und Lehrbrief: Abweichungen.
    Typische Fehlerbilder: Fehlerbildkatalog.
    KI-Einsatz gem. KI-Nutzungsrichtlinie: In dieser Aufgabe bearbeitet ihr alle Teile ohne KI.

    Alle Abfragen beziehen sich auf die Datenbank BestTec aus der Übung. Bei den Teilen A und B steht jeweils die Zeilenzahl dabei, mit der ihr euer Ergebnis kontrollieren könnt.

    Teil A — Zeilen filtern und sortieren ca. 10 Min.

    1. Gesucht sind alle Mitarbeiter, die einem von zwei Profilen entsprechen: Entweder ist das Grundgehalt kleiner als 5000 und die Tätigkeit weder Programmierer noch Administrator, oder die Tätigkeit ist Controller oder Trainer. Ausgabe: Name, Abteilungsnummer, Tätigkeit, Gehalt. (Aufgabe nach Lehrbrief, Kap. 7.10, Nr. 4, S. 88; Kontrolle: 12 Zeilen)

    Musterlösung A.1 anzeigen 
    -- A1: Zwei Profile (Lehrbrief-Aufgabe 4)
SELECT name, abtnr, job, gehalt
FROM ma
WHERE (gehalt < 5000 AND job NOT IN ('Programmierer', 'Administrator'))
   OR job IN ('Controller', 'Trainer');

    Die beiden Profile sind zwei Bedingungen, die mit OR verbunden werden; die Klammern um das erste Profil machen die Struktur sichtbar. Die Bedingung NOT IN mit „Administrator“ schadet nicht, obwohl es diese Tätigkeit nicht gibt.

    2. Welche Mitarbeiter verdienen zwischen 2800 und 3000 € (einschließlich der Grenzen)? Ausgabe: Name und Gehalt, das höchste Gehalt zuerst, bei Gleichstand alphabetisch nach Name. (Kontrolle: 4 Zeilen)

    Musterlösung A.2 anzeigen 
    -- A2: Gehalt zwischen 2800 und 3000, höchstes zuerst, bei Gleichstand nach Name
SELECT name, gehalt
FROM ma
WHERE gehalt BETWEEN 2800 AND 3000
ORDER BY gehalt DESC, name;

    BETWEEN schließt beide Grenzen ein. Frohn, Schulte und Holle verdienen gleich viel (2900) — das zweite Sortierkriterium entscheidet über ihre Reihenfolge.

    3. Welche Mitarbeiter haben einen Namen, der mit „M“ beginnt, und sind keine Manager? Ausgabe: Name, Tätigkeit, Abteilungsnummer. (Kontrolle: 2 Zeilen)

    Musterlösung A.3 anzeigen 
    -- A3: Namen mit M am Anfang, kein Manager
SELECT name, job, abtnr
FROM ma
WHERE name LIKE 'M%' AND job <> 'Manager';

    Der zweite Meier (Abteilung 40) ist Manager und fällt heraus; es bleiben Meier (Projektleiter) und Meyer.

    4. Wie hoch ist das Jahresgehalt (zwölf Monatsgehälter) der Mitarbeiter der Abteilung 30? Ausgabe: Name und Jahresgehalt, das höchste zuerst. (Kontrolle: 3 Zeilen)

    Musterlösung A.4 anzeigen 
    -- A4: Jahresgehalt der Abteilung 30
SELECT name, gehalt * 12 AS jahresgehalt
FROM ma
WHERE abtnr = 30
ORDER BY jahresgehalt DESC;

    Der Alias jahresgehalt darf in ORDER BY verwendet werden.

    Teil B — Über mehrere Tabellen abfragen ca. 12 Min.

    1. Welche Projekte finden in der Abteilung von Mitarbeiter 7739 statt? Ausgabe: Abteilungsnummer, Bezeichnung, Titel, Kundennummer. (Lehrbrief, Nr. 7, S. 88; Kontrolle: 3 Zeilen)

    Musterlösung B.1 anzeigen 
    -- B1: Projekte in der Abteilung von Mitarbeiter 7739 (Lehrbrief-Aufgabe 7)
SELECT a.abtnr, a.bezeichnung, p.titel, p.kdnr
FROM ma m, abt a, prj p
WHERE m.manr = 7739 AND m.abtnr = a.abtnr AND a.abtnr = p.abtnr;

    Hier werden drei Tabellen verknüpft, also braucht es zwei Verknüpfungsbedingungen (Mitarbeiter–Abteilung und Abteilung–Projekt). Faustregel: n Tabellen, n − 1 Verknüpfungen.

    2. Welche Projekte gehören zu Abteilungen, in denen es Mitarbeiter gibt, die Engineer oder Programmierer sind? Ausgabe wie bei 1. Wie viele Zeilen entstehen, wenn ihr DISTINCT weglasst — und warum? (Lehrbrief, Nr. 8, S. 88; Kontrolle mit DISTINCT: 3 Zeilen)

    Musterlösung B.2 anzeigen 
    -- B2: Projekte von Abteilungen mit Engineers oder Programmierern (Lehrbrief-Aufgabe 8)
-- DISTINCT verhindert, dass ein Projekt pro passendem Mitarbeiter erscheint
SELECT DISTINCT a.abtnr, a.bezeichnung, p.titel, p.kdnr
FROM ma m, abt a, prj p
WHERE m.job IN ('Engineer', 'Programmierer')
  AND m.abtnr = a.abtnr AND a.abtnr = p.abtnr;

    Ohne DISTINCT entstehen 12 Zeilen: Abteilung 20 hat vier Mitarbeiter mit passender Tätigkeit (Frohn, Werther, Meyer, Sorge) und drei Projekte, und der Verbund erzeugt jede Kombination. Das ist ein typisches Fehlerbild (F2 im Fehlerbildkatalog).

    3. Welche Mitarbeiter arbeiten in Abteilungen mit Sitz in Verl oder Münster? Ausgabe: Name, Bezeichnung der Abteilung und Sitz, sortiert nach Sitz und Name. (Kontrolle: 9 Zeilen)

    Musterlösung B.3 anzeigen 
    -- B3: Mitarbeiter in Verl oder Münster mit Abteilung und Sitz
SELECT m.name, a.bezeichnung, a.sitz
FROM ma m, abt a
WHERE m.abtnr = a.abtnr AND a.sitz IN ('Verl', 'Münster')
ORDER BY a.sitz, m.name;

    Die Sortierung nach a.sitz und m.name kann sich auf Spalten beider Tabellen beziehen.

    4. Welche Mitarbeiter arbeiten in Abteilungen, die ein Projekt für den Kunden „M341“ durchführen? Ausgabe: Name und Tätigkeit, jeder Mitarbeiter nur einmal. (Kontrolle: 6 Zeilen)

    Musterlösung B.4 anzeigen 
    -- B4: Mitarbeiter von Abteilungen mit einem Projekt für Kunde M341
SELECT DISTINCT m.name, m.job
FROM ma m, abt a, prj p
WHERE m.abtnr = a.abtnr AND a.abtnr = p.abtnr AND p.kdnr = 'M341'
ORDER BY m.name;

    Beide M341-Projekte (232 und 256) gehören zu Abteilung 20. Ohne DISTINCT stünde jeder der sechs Mitarbeiter zweimal im Ergebnis.

    Teil C — Ergebnis vorhersagen ca. 8 Min.

    Zu jeder Abfrage beantwortet ihr zwei Fragen: Was ist ihr Ziel, und was liefert sie tatsächlich? Leitet das Ergebnis jeweils zuerst von Hand aus den Tabellen auf der Seite BestTec: Datenbestand her, bevor ihr eine Antwort wählt. Prüft es erst danach in SQL Server.

    Abfrage 1

    SELECT x.name, x.gehalt, y.name AS chef, y.gehalt AS chefgehalt
FROM ma x, ma y
WHERE x.vorgnr = y.manr AND x.gehalt > y.gehalt;
    #

    Was ist das Ziel dieser Abfrage?

    Falsch: Die Rollen sind vertauscht. Ausgegeben und verglichen wird mit x.gehalt > y.gehalt, also das Gehalt des Untergebenen gegen das des Vorgesetzten.
    Falsch: Verglichen wird mit dem jeweiligen direkten Vorgesetzten (vorgnr), nicht mit einer festen Person. Nur bei Mitarbeitern, die Hansen unterstellt sind, wäre das zufällig derselbe.
    Richtig: x ist der Untergebene, y der Vorgesetzte (x.vorgnr = y.manr). Die Bedingung x.gehalt > y.gehalt wählt die Untergebenen aus, die mehr verdienen als der Vorgesetzte.
    Falsch: Die Verknüpfung läuft über vorgnr = manr, nicht über die Abteilungsnummer.
    Falsch: Das wäre die Abfrage ohne AND x.gehalt > y.gehalt. Die zusätzliche Bedingung schränkt das Ergebnis ein.
    #

    Welches Ergebnis liefert die Abfrage?

    Falsch: Das wäre das Ergebnis ohne die Gehaltsbedingung. Mit x.gehalt > y.gehalt bleiben nur Mitarbeiter, die mehr verdienen als ihr Vorgesetzter.
    Falsch: Meyer (5200) und Sorge (5800) haben beide Karl (7200) als Vorgesetzten und verdienen weniger als er.
    Falsch: Hansen hat keinen Vorgesetzten (vorgnr ist NULL). Er fällt schon bei der Verknüpfung heraus und erscheint nie im Ergebnis.
    Richtig: Kein Mitarbeiter verdient mehr als sein direkter Vorgesetzter. Ein leeres Ergebnis ist hier ein korrektes Ergebnis, kein Fehler.
    Falsch: Mit zwei verschiedenen Aliasen (x, y) darf dieselbe Tabelle mehrfach im FROM-Teil stehen. Das ist der Selbstverbund.

    Abfrage 2

    SELECT a.bezeichnung, p.titel
FROM abt a, prj p
WHERE a.abtnr = 20;
    #

    Was soll diese Abfrage erkennbar leisten?

    Falsch: Die Abfrage schränkt mit a.abtnr = 20 auf eine einzige Abteilung ein, es sind also nicht alle Projekte gemeint.
    Richtig, das ist die erkennbare Absicht: Ausgegeben werden Abteilungsbezeichnung und Projekttitel, eingeschränkt auf Abteilung 20. Ob die Abfrage das auch erreicht, zeigt die nächste Frage.
    Falsch: Es gibt weder eine Gruppenfunktion noch GROUP BY; ausgegeben werden einzelne Projekttitel.
    Falsch: Die Abfrage ist auf Abteilung 20 eingeschränkt, nicht auf Abteilungen mit Projekten.
    Falsch: In der Auswahlliste steht auch a.bezeichnung, die Abteilung wird also mit ausgegeben.
    #

    Welches Ergebnis liefert die Abfrage?

    Falsch: Das wäre das Ergebnis mit der zusätzlichen Bedingung a.abtnr = p.abtnr. Sie fehlt, deshalb bleibt es nicht bei den eigenen Projekten.
    Richtig: Die Bedingung a.abtnr = 20 wählt genau eine Zeile aus abt (Engineering). Ohne Verknüpfung mit prj wird sie mit jedem der vier Projekte kombiniert, auch mit AutoRob der Zentrale. Das ist das Fehlerbild F1 im Fehlerbildkatalog.
    Falsch: Das wäre das Ergebnis ganz ohne WHERE. Hier wird abt auf eine Zeile eingeschränkt.
    Falsch: Es gibt keine Regel, die auf ein einzelnes Projekt einschränkt. Alle vier Kombinationen erfüllen die Bedingung.
    Falsch: SQL Server prüft die Syntax, nicht den Sinn der Abfrage. Eine fehlende Verknüpfung bemerkt die Datenbank nicht.

FROM ma m, abt a
WHERE m.abtnr = a.abtnr
  AND a.sitz IN ('Verl', 'Paderborn')
  AND m.job <> 'Engineer';

SELECT m.name, a.bezeichnung
FROM ma m, abt a
WHERE a.sitz IN ('Verl', 'Paderborn')
  AND m.job <> 'Engineer';

-- c) AND/OR ohne Klammern
SELECT m.name, a.bezeichnung
FROM ma m, abt a
WHERE m.abtnr = a.abtnr

WHERE m.abtnr = a.abtnr

  AND m.job = 'Engineer';
