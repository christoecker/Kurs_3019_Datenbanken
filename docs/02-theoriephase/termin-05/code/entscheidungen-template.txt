## 2. Entscheidungen

Je Entscheidung ein Abschnitt. Erlaubte Werte:

- `bereich`: schema, constraint, recht, prozedur, trigger, abfrage, sonstiges
- `phase`: v1 (vor dem Zwischentermin), v2 (danach)
- `herkunft`: selbst, ki-uebernommen, ki-korrigiert, ki-verworfen

### E01

bereich: schema
phase: v1
entscheidung: Beispiel (aus einem anderen Projekt, einer Werkzeugausgabe): Werkzeug und Ausleihe liegen in getrennten Tabellen.
begruendung: Ein Werkzeug wird oft ausgeliehen; in einer einzigen Tabelle würden die Werkzeugdaten bei jeder Ausleihe wiederholt.
alternative: Eine Tabelle mit allen Angaben. Verworfen wegen der Wiederholungen und weil Änderungen am Werkzeug an vielen Stellen nötig wären.
herkunft: selbst

### E02

bereich: constraint
phase: v1
entscheidung: Beispiel (Werkzeugausgabe): Das Rückgabedatum darf nicht vor dem Ausleihdatum liegen, geprüft mit einem CHECK.
begruendung: Die Regel betrifft nur zwei Spalten derselben Zeile, deshalb reicht ein Constraint; er gilt für jeden Weg, auf dem Daten ankommen.
alternative: Prüfung in der Prozedur. Verworfen, weil direkte INSERTs sie umgehen würden.
herkunft: ki-korrigiert
